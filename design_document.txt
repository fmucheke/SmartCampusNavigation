# DESIGN DOCUMENT – Smart Campus Navigation

Team: Urisha Shrestha, Franklin Mucheke, Samriddi Upreti

## 1. Program Overview
Our program helps users find campus facilities, navigate between buildings and explore the department hierarchy. We used a custom hash table, a graph and a general tree. The program loads buildings.txt, connections.txt, facilities.txt and departments.txt in that order. Invalid records are rejected with warnings.

## 2. Hash Table
We created a custom hash table to make facility ID searches faster.

Hash function: Start with h = 0. For each character c in the standardized ID, calculate h = (h * 31 + c) % capacity.

The capacity is fixed at 101 buckets. We used separate chaining, where each bucket contains a vector of facilities. For example, F001 and F039 both go into bucket 16. A collision is counted when a new facility is successfully inserted into an occupied bucket. Duplicate IDs are rejected.

Name and category searches use case-insensitive linear search. The category report displays facility counts and percentages.

## 3. Campus Graph
We used an undirected graph with an adjacency list because it stores only existing connections and saves space.

Breadth-First Search (BFS) uses a queue to find reachable buildings. The shortest path function also uses BFS and remembers previous buildings to reconstruct the path with the fewest connections.

The connectivity report displays building and connection counts, highest-degree buildings, isolated buildings and connected components.

## 4. Department Tree
We used a general tree because departments can have multiple children. Each node stores its name, parent pointer and vector of children. Duplicate names and unknown parents are rejected.

Preorder visits parents first, postorder visits children first and level-order visits departments one level at a time. Preorder and postorder use recursion, while level-order uses a queue.

Department statistics include total departments, leaves, height in edges and maximum direct children. The destructor deletes children before their parents to release memory.

## 5. Time Complexity
F = facilities, V = buildings, E = connections, D = departments, C = categories.

- Facility ID search: O(1) average with short chains, O(F) worst case.
- Facility name/category search: O(F).
- Category report: O(F × C), worst case O(F²).
- BFS, shortest path and connectivity report: O(V + E).
- Department addition, search, traversals, statistics and deletion: O(D).

These calculations assume constant-time name comparisons.

## 6. Program Organization
FacilityManager and HashTable manage facilities. CampusGraph and GraphLoader manage buildings and connections. DepartmentTree and DepartmentNode manage departments. FileUtils provides shared name-standardization functions, and main.cpp connects all modules.

We separated these modules to make teamwork, testing and debugging easier. Individual contributions and testing details are recorded in CONTRIBUTIONS.txt and test_results.txt.
