## 1. WHAT THE PROGRAM DOES

Our program helps people find their way around a college campus. Users can search for facilities, see how buildings are connected, find the shortest path between two buildings and explore how departments are organized.

The program reads information from four text files in the following order:

- buildings.txt
- connections.txt
- facilities.txt
- departments.txt

We load the buildings first because the program needs to know which buildings exist before adding connections and facilities.

After reading each file, the program shows how many records were accepted and rejected. If something is wrong with a record, it displays the file name, line number and reason. It continues reading the rest of the file instead of stopping.

For our Final submission, we expanded the program to have 18 menu options.

## 2. HASH TABLE AND FACILITY MANAGEMENT

We used a hash table to make searching for facilities by their IDs easier and faster.

Think of a hash table as a collection of numbered boxes. Instead of looking through every facility, the program calculates which box the facility belongs to and searches there.

We created our own hash table without using a built-in library hash table.

A facility ID must start with F followed by three digits, such as F004. The program removes extra spaces and ignores capitalization, so f004 and F004 are treated as the same ID.

### Hash Function

The hash function helps the program decide which bucket (box) a facility belongs to.

- Start with h = 0.
- Read each character c in the facility ID.
- Calculate h = (h * 31 + c) mod capacity.
- Use the final value of h as the bucket number.

Our hash table has 101 buckets by default.

### Handling Collisions

Sometimes two different facility IDs end up in the same bucket. This is called a collision.

We used a method called separate chaining to handle this. Each bucket contains a vector that can hold multiple facilities. This means we do not have to reject a facility just because another facility is already in that bucket.

For example, F001 and F039 both go into bucket 16.

A collision is counted when a new facility is successfully added to a bucket that already contains another facility. Duplicate IDs are rejected and do not increase the collision count.

The hash table does not resize, but the vectors inside the buckets can grow.

### Searching for Facilities

There are three ways to search for a facility:

- By ID
- By name
- By category

Searching by ID uses the hash table. Searching by name or category checks the facilities one by one, which is called linear search.

The name and category searches ignore capitalization and display all exact matches. The program also shows how many matches were found.

### Facility Category Report

This report helps users understand what types of facilities are available on campus.

The program groups facilities with the same category and counts how many belong to each group. It then calculates their percentages.

Percentage = (Number of facilities in a category / Total facilities) * 100

For example, if there are 10 facilities and 4 of them are laboratories, laboratories make up 40% of the facilities.

The percentages are displayed with one decimal place. If there are no facilities, the program displays a message and a total of zero.

## 3. CAMPUS GRAPH

We used a graph to represent the campus buildings and the walkways between them.

Each building is a vertex, and each connection between two buildings is an edge.

We stored the graph using an adjacency list. This simply means that every building has its own list of neighboring buildings.

We chose this method because not every building is connected to every other building. Storing only the existing connections saves memory compared to storing a full table of possible connections.

The connections work both ways. If Building A is connected to Building B, then Building B is also connected to Building A. However, this connection is counted only once.

The program rejects duplicate connections, unknown buildings and connections from a building to itself.

### BFS Reachability

BFS stands for Breadth-First Search.

It helps us find which buildings can be reached from a selected building. It starts by visiting the closest neighboring buildings before moving farther away.

We used a queue for this process. A queue works like a line of people waiting for their turn. The building added first is processed first.

The program keeps track of buildings it has already visited so that it does not visit the same building repeatedly.

It also displays how many connections away each building is from the starting point and the total number of reachable buildings.

### Shortest Path

For the Final, we added a function that finds the shortest path between two buildings.

We used BFS again because all connections in our graph are treated equally. The shortest path means the path with the fewest connections, not necessarily the shortest walking distance in meters.

While searching, the program remembers which building it came from. Once it reaches the destination, it follows those buildings backward and reverses the result to show the path in the correct order.

If there are multiple shortest paths, the program follows the order in which the connections were originally added.

It also handles cases where a building does not exist, there is no available path or the starting and ending buildings are the same.

### Graph Connectivity Report

This report gives users an overview of how well the campus buildings are connected.

It displays:

- Total number of buildings.
- Total number of connections.
- Buildings with the most connections.
- Buildings with no connections.
- Number of connected components.

A connected component is a group of buildings that can reach each other.

For example, if five buildings are connected to each other but another building is completely separate, there are two connected components.

The program uses BFS to identify and count these groups.

## 4. DEPARTMENT TREE

We used a general tree to organize the university departments.

A general tree is useful because a department can have more than one department under it. It is similar to how folders are organized inside other folders on a computer.

For example:

    University
        College of Engineering
            Computer Science
            Electrical Engineering
        College of Science
            Mathematics
            Physics

Each department has a name, a pointer to its parent and a vector containing its children.

The University in this example is called the root because it is at the top of the tree.

The first accepted department from the file must have NONE as its parent. Every other department needs a parent that already exists.

We do not allow duplicate department names, even if they have different capitalization.

### Adding and Searching Departments

Users can add new departments through the menu.

If the tree is empty, the first department becomes the root. Otherwise, the user needs to provide an existing parent department.

New departments are stored in memory while the program is running. They do not change the original departments.txt file.

When searching for a department, the program displays its name, parent, number of direct children and depth.

Depth tells us how far a department is from the root.

### Displaying the Hierarchy

The program displays the department hierarchy using four spaces of indentation for each level. This makes it easier to understand which departments belong under others.

### Tree Traversals

A traversal is simply a way of visiting every department in the tree.

We used three types of traversals:

**Preorder:** Visits the parent first and then its children.

**Postorder:** Visits the children first and then their parent.

**Level-order:** Visits departments one level at a time, starting from the root.

Preorder and postorder use recursion, which means a function calls itself to repeat the same task for smaller parts of the tree.

Level-order uses a queue.

All three traversals keep the departments in their original insertion order when visiting siblings.

### Department Statistics

For the Final, we added four statistics to help users understand the department structure.

**Total departments:** Counts all the departments in the tree.

**Leaf departments:** Counts departments that do not have any children.

**Tree height:** Shows the longest distance from the root to a leaf, measured in edges.

**Maximum number of children:** Finds the largest number of direct children belonging to any single department.

Using the university example above, the statistics would be:

- Total departments: 7
- Leaf departments: 4
- Tree height: 2
- Maximum number of children: 2

If the tree is empty, the counts are zero and the height is displayed as N/A.

If there is only one department, the total departments and leaves are both one. The height and maximum number of children are zero.

### Memory Management

The department nodes are created in memory while the program runs.

When the program closes, the destructor deletes the child departments first and then their parents. This releases the memory used by the department tree.

## 5. MAIN CLASSES AND FILES

Each class has its own responsibility. We separated the program into different files so that it would be easier to understand, test and make changes.

- Facility: Stores information about one facility.
- FacilityManager: Loads, displays and searches facilities. It also creates the category report.
- HashTable: Stores facilities and helps find them by ID.
- CampusGraph: Stores buildings and connections, performs BFS, finds shortest paths and creates the connectivity report.
- GraphLoader: Reads and checks the building and connection files.
- DepartmentNode: Stores information about one department.
- DepartmentTree: Manages departments, traversals and department statistics.
- FileUtils: Contains shared functions for removing extra spaces and changing letters to uppercase.
- main.cpp: Loads the files, displays the menu and connects all parts of the program.

## 7. TIME COMPLEXITY

Time complexity helps us understand how much work the program needs to do when more data is added.

For example, O(1) means an operation takes roughly the same amount of work, while O(n) means the amount of work increases with the number of records.

We used the following variables:

- F = Number of facilities.
- V = Number of buildings.
- E = Number of connections.
- D = Number of departments.
- C = Number of different facility categories.

### Hash Table and Facilities

| Operation | Time Complexity |
|---|---|
| Search by ID | O(1) average with short chains, O(F) worst case |
| Hash table insertion | O(1) average with short chains, O(F) worst case |
| Display all facilities | O(F) |
| Search by name | O(F) |
| Search by category | O(F) |
| Category report | O(F * C) |

Searching by ID is usually faster because the hash table tells us which bucket to check.

Searching by name or category takes longer as more facilities are added because the program checks each facility.

The category report checks the existing categories for every facility. If every facility has a different category, the worst-case time complexity becomes O(F²).

Since our hash table has a fixed number of buckets, searching may become slower if the chains grow longer.

### Campus Graph

| Operation | Time Complexity |
|---|---|
| Find building by name | O(V) |
| Display graph | O(V + E) |
| Display building degrees | O(V) |
| BFS reachability | O(V + E) |
| Shortest path | O(V + E) |
| Connectivity report | O(V + E) |

BFS checks each reachable building and its connections. As the number of buildings and connections increases, the program has more information to process.

### Department Tree

| Operation | Time Complexity |
|---|---|
| Add department | O(D) |
| Search department | O(D) |
| Display hierarchy | O(D) node visits |
| Preorder traversal | O(D) |
| Postorder traversal | O(D) |
| Level-order traversal | O(D) |
| Department statistics | O(D) |
| Delete the tree | O(D) |

Adding a department requires checking for duplicate names and finding its parent.

The traversals visit every department. The statistics functions also check the departments to calculate their results.

These calculations assume that comparing names takes constant time. Displaying the hierarchy may take extra time depending on the amount of indentation needed.
